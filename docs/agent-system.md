# エージェントシステム

## 概要

halfeyeのAIは「画面を見てコメントする」だけの受動的な存在ではなく、**文脈を理解し、思考し、行動を選択するエージェント**として設計する。

現在の単純な「刺激→反応」ループを、ReAct（Reasoning + Acting）パターンに基づくエージェントサイクルへ段階的に進化させる。

---

## 現在のアーキテクチャ（v0）

```
[10秒ごと]
  キャプチャ → 固定プロンプト + 画像 → Gemini API → リアクションテキスト
```

- 各リアクションは独立（前回の文脈なし）
- 毎回必ずリアクションを出力
- 思考過程は存在しない（プロンプトが直接リアクションを要求）

---

## Phase 1: ReActサイクル + 文脈蓄積

### サイクル構造

```
[10秒ごと]
  Observe: スクリーンキャプチャ
      ↓
  Think + Act: 画像 + 直近の文脈 → Gemini API → { thought, reaction }
      ↓
  Output: reaction をオーバーレイに表示、thought は内部ログとして保存
```

1回のAPI呼び出しで思考（thought）と行動（reaction）をJSON構造で同時出力する。10秒間隔のサイクルでAPI複数回呼び出しは遅延が大きすぎるため、1回で完結させる。

### JSON出力スキーマ

Gemini APIの `response_mime_type: "application/json"` と `response_schema` を使用してJSON出力を強制する。

```json
{
  "thought": "ユーザーはVSCodeでRustのコードを書いている。前回はコンパイルエラーが出ていたが、今回は修正済みのようだ。",
  "reaction": "エラー直りましたね！コンパイル通ってますよ。"
}
```

### 文脈蓄積

Gemini APIのマルチターンcontents配列を活用し、直近5件のリアクション履歴を会話形式で渡す。

```
system_instruction: ReActシステムプロンプト（固定）

contents[0]: { role: "user",  parts: [テキスト: "キャプチャ at 10:00:00"] }
contents[1]: { role: "model", parts: ['{"thought":"...","reaction":"..."}'] }
contents[2]: { role: "user",  parts: [テキスト: "キャプチャ at 10:00:10"] }
contents[3]: { role: "model", parts: ['{"thought":"...","reaction":"..."}'] }
...
contents[N]: { role: "user",  parts: [画像(今回), テキスト: "画面を観察してください"] }
```

**設計判断:**
- 過去ターンには画像を含めない（テキストのみ）。トークンコストの抑制が目的
- 画像は最新1枚のみ送信。過去の画面内容はthoughtに要約されている
- 5件 ≒ 約50秒分。短期的な画面変化を追跡するには十分な量

### デバッグログ

AIの全行動（thought含む）はDBに保存し、フロントエンドから閲覧可能にする。ユーザーにはreactionのみ表示するが、デバッグモードではthoughtも確認できる。

```sql
-- reactionsテーブルにthoughtカラムを追加
ALTER TABLE reactions ADD COLUMN thought TEXT;
```

## Phase 2: 自律的な行動選択（将来）

### 概要

Phase 1では毎回必ずリアクションを出力するが、Phase 2ではAI自身が「今リアクションすべきか」を判断する。

### 拡張されたJSON出力スキーマ

```json
{
  "thought": "前回と画面がほぼ同じ。ユーザーはじっくり読んでいるようだ。今は黙っていよう。",
  "action_type": "silent",
  "reaction": null
}
```

```json
{
  "thought": "画面が大きく変わった。新しいアプリケーションを開いたようだ。",
  "action_type": "react",
  "reaction": "おっ、新しいツール使い始めたんですね！"
}
```

`action_type` の候補:
- `react` — リアクションを表示する
- `silent` — 黙る（thoughtはログに残す）

### 動的キャプチャ間隔

thoughtの中で「次のキャプチャまでの推奨間隔」を出力させることも検討。変化が激しい場面では短く、変化がない場面では長くする。

## Phase 3: ツール使用（将来）

### 概要

AIがリアクション以外のアクションを「ツール呼び出し」として選択できるようにする。

### 拡張されたJSON出力スキーマ

```json
{
  "thought": "ユーザーがエラーメッセージを見ているが、小さくて読めない。拡大して確認したい。",
  "action_type": "tool_call",
  "reaction": null,
  "tool_call": {
    "name": "adjust_capture",
    "args": { "region": "center", "zoom": 2.0 }
  }
}
```

### ツール候補

| ツール名 | 説明 |
|---|---|
| `adjust_capture` | キャプチャの領域や解像度を動的に変更 |
| `change_interval` | キャプチャ間隔を変更 |
| `set_overlay_style` | オーバーレイの表示スタイルを変更 |
| `request_attention` | 重要なリアクションをより目立たせる |

### Agenticループ

Phase 3ではツール呼び出しの結果を踏まえた再推論が可能になる。1サイクル内で複数回のThink→Actが発生しうる。

```
Observe → Think → Tool Call → Observe (結果) → Think → Act
```

## 長期コンテキスト（将来）

Phase 1の文脈蓄積（直近5件）は短期記憶に相当する。長期的な文脈の蓄積も今後検討する。

### 検討中のアプローチ

- **セッション中間サマリー**: 一定間隔（例: 5分ごと）で直近のリアクション群を要約し、長期記憶としてプロンプトに含める
- **セッション間の接続**: 過去セッションのサマリーを参照し、「前回の続き」を認識する
- **構造化メモリ**: 重要な事実やトピックをキー/バリュー形式で蓄積し、必要に応じて参照する

```
プロンプト構成（将来像）:
  system_instruction: エージェントの基本設定
  長期コンテキスト: セッション間サマリー、ユーザープロファイル等
  中期コンテキスト: セッション中間サマリー
  短期コンテキスト: 直近5件のリアクション履歴（マルチターン）
  現在の入力: 最新のスクリーンショット
```

## サマリーシステムの進化（将来）

現在のサマリーは「全リアクションログ → 簡潔な要約1つ」というシンプルな構造。将来的には以下を目指す。

### 議事録レベルのサマリー

- 時系列に沿った詳細な記録
- トピックごとの整理
- 決定事項や重要ポイントの抽出

### コンテンツ適応型

- コンテンツの種類（会議、ゲーム、作業等）に応じてサマリーの形式やUIを変える
- AIがコンテンツ種類を自動判別し、適切なテンプレートを選択する
